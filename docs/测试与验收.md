## 自动检查

- 后端：`mvn spotless:check test`，2项纯业务单元测试、13项实际Spring上下文集成测试；H2运行相同Flyway迁移并验证实体结构。
- 前端：`npm ci`、`npm run format:check`、`npm run lint`、`npm test`（4项请求与导入校验测试）、`npm run build`。
- 容器：`docker compose config --quiet`、`docker compose build`；镜像构建保留所有测试。
- 发布：`python3 scripts/release-check.py`、`git diff --check`，核查图片、源码署名、授权、忽略配置与常见凭证模式。

开发集成测试使用明确的`TestOnly-...`密码，仅在测试资源中，不是产品默认密码。敏感信息模式扫描不是完整安全审计，应结合人工差异审查。

## 全新MySQL与HTTP验收

在独立Compose项目中首次创建数据库和附件卷，检查服务健康，然后运行`python3 scripts/smoke.py --allow-test-data`。默认地址http://127.0.0.1:8198，可用`--url`改为独立测试端口。

16项HTTP验收覆盖：前端与SPA路径、健康、匿名与错误密码、CSRF、角色限制与散列脱敏、完整维修／库存／复核／确认／结算、报价前置条件、库存幂等与不足、并发超卖、客户和工程师范围、计划重复触发、导入回滚、版本与状态及CSV、等待恢复及复核退回、本地建议真实来源、修改密码使其他旧会话失效、附件真实上传下载与范围隔离。

另需实际核查MySQL`flyway_schema_history`成功记录，重启后端后再次登录并核对已关闭工单、库存、审计仍在，浏览器执行资料新增／编辑、工单操作、文件上传和下载，并检查移动宽度布局。六类截图直接保存当前运行页面，测试资料明确标注，密码或Cookie不出现在截图中。

## 发布前验收清单

1. 全部自动检查及镜像构建成功，不能跳过测试。
2. 数据库、后端、前端健康，管理员可登录，核心流程完整。
3. 越权、版本冲突、非法状态和库存不足拒绝；并发测试不超卖。
4. 全新迁移成功，重启后数据持久化且已有管理员不重复初始化。
5. README六图、两个二维码、Logo、官网、微信号和LICENSE正确。
6. 对外说明区分已实现、本地规则及未实现功能，不含会话叙述或虚构客户。
7. 审阅Git差异，提交仅限项目文件；不包含配置、业务数据、日志和凭证。
8. 获得发布授权后推送实际配置远程，逐平台核实公开可见及提交SHA。
9. 只停止并清理本次独立测试容器及测试卷，确认Git工作区。

本文件描述验收方法，不代替某次发布的实际检查结果；具体结果见对应版本交付记录。
