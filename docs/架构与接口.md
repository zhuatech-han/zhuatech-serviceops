## 模块边界

`Access`每次访问读取有效账号、组织及权限；`Catalog`维护主数据并限制分页字段；`Orders`处理权益快照与状态；`Inventory`处理行锁、幂等和成本；`Maintenance`按计划日期生成请求；`Files`控制上传及下载；`Admin`管理账号角色；`AdviceAdapter`只返回建议；`Views`脱敏客户成本输出。

同实例内以`orgId`分隔部门，不提供独立数据库租户。账号、角色与部门由管理员统一管理。业务查询使用绑定参数，修改需要版本。库存按“工单→备件”顺序加锁，同一工单的库存与状态处理串行。原领用流水的退回和消耗在相同锁范围核销，唯一键限制请求复用与计划重复。

订单状态：PENDING、DISPATCHED、IN_PROGRESS、WAIT_PARTS、WAIT_CUSTOMER、REVIEW、CONFIRM、CLOSED、CANCELLED。收费报价确认与结算状态独立于服务状态。没有自动执行AI工具、自动审批或在线支付。

## 会话与通用约定

登录前`GET /api/auth/csrf`获取`token`和`headerName`，所有写请求添加该头。使用同源Cookie，不把会话令牌存到localStorage。登录后重新获取CSRF，Spring Security会轮换认证会话。有效会话30分钟，HTTP错误返回`message`；401重新登录，403无权限或CSRF失败，404不在可见范围，409状态／版本／唯一约束冲突。

JSON时间戳为UTC的无后缀本地格式，前端显式按UTC解析。金额最多两位小数且非负。创建字段使用白名单；版本更新传`version`。主数据停用保留记录，不改变历史工单。

| 方法与路径 | 业务与权限 |
|---|---|
| POST `/api/auth/login` | URL编码username/password；保留CSRF检查 |
| GET `/api/auth/me` | 当前账号与权限；不包含密码散列 |
| POST `/api/auth/logout` | 注销当前会话 |
| POST `/api/auth/password` | oldPassword/newPassword；修改后旧会话拒绝访问 |
| GET `/api/catalog/{kind}` | q/page/size/sort/state；按模块读权限；size最多100 |
| POST/PUT `/api/catalog/{kind}[/{id}]` | customers/assets/contracts/parts/plans/knowledge/config；对应写权限 |
| DELETE `/api/catalog/{kind}/{id}?version=...` | 停用或撤下发布；非物理删除 |
| POST `/api/catalog/{customers\|parts}/import` | 1至100条对象；整批事务 |
| GET `/api/admin` | 管理员读取账号、角色、组织 |
| POST/PUT `/api/admin/{users\|roles\|organizations}[/{id}]` | 管理员维护；不可停用或降权自己 |
| POST `/api/orders` | orders.create；assetId/name/description/priority |
| GET `/api/orders/{id}` | orders.read及数据范围；客户成本脱敏 |
| POST `/api/orders/{id}/{action}` | version与动作字段；检查功能权限、状态及数据范围 |
| POST `/api/inventory/movements` | RECEIVE/ISSUE/RETURN/CONSUME；库存写／执行权限 |
| POST `/api/plans/trigger` | plans.manage；仅触发到期计划 |
| POST `/api/orders/{id}/attachments` | multipart file；orders.execute；5MB限制 |
| GET `/api/attachments/{id}` | orders.read及对应工单范围；下载附件 |
| GET `/api/lookups` | 可指派工程师，不返回登录凭证 |
| GET `/api/dashboard` | orders.read；范围内统计，财务项需report.read |
| GET `/api/reports/orders.csv` | report.read；筛选导出至多5000条 |
| GET `/api/orders/{id}/advice?q=...` | knowledge.read/orders.read；本地规则和至多5条已发布资料 |
| GET `/actuator/health` | 后端健康；Nginx对外仅`/health` |

库存字段：`partId`、`kind`、`quantity`、`requestKey`、`reason`；非入库追加`orderId`，消耗／退回追加`issueId`。幂等键只可复用于完全相同的类型、数量、备件、工单和原领用编号，冲突返回409。

工单动作字段：dispatch用assigneeId；quote用quotedAmount/reason；wait-parts、wait-customer、reject、cancel、reopen用reason；finish用diagnosis/resolution/laborMinutes/safetyChecked/testPassed；settle用paymentReference；其他动作只需version。

## 后续扩展方向

保持服务请求、库存台账、权限与审计边界，后续按新增迁移引入预约、技能、SLA工作日历和移动作业；对外系统先建立版本化事件、外部编号、重试及审计，再实现连接器。AI扩展通过AdviceAdapter提供建议与证据来源，执行业务仍走同一权限和状态接口。以上为路线，均不属于0.1.0已实现功能。
