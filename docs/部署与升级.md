## 学习环境

本版自有代码仅限个人学习、技术研究与非商业交流。企业部署及商业交付须取得书面授权。环境：Docker、Compose v2、可联网下载镜像与依赖；建议至少4GB可用内存及足够镜像磁盘空间，不是性能容量承诺。

根目录执行：

```bash
python3 scripts/init-env.py
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 240
docker compose ps
```

前端http://127.0.0.1:8198；健康http://127.0.0.1:8198/health。首次admin密码查看本机`.env`。Docker构建执行后端测试及前端格式、静态检查、测试、构建，不能跳过。Maven使用BuildKit缓存锁和依赖预取，下载失败会重试。

数据库和后端只在容器网络内可达；Web默认只绑定本机；MySQL卷与附件卷分别持久化。后端UID10001、前端nginx用户执行，MySQL按官方镜像方式初始化。数据卷继承镜像内目录所有权，迁移已有附件文件时保证后端UID10001可读写。

## 参数与升级

`.env`仅在本机保存。更改已有卷的数据库密码需要明确数据库账号变更步骤，不能仅改环境变量；初始管理员环境密码也不能重设已存在账号。

升级前备份完整数据库与附件卷，并在独立环境恢复验证。先记录当前Git版本及镜像，再构建新镜像、使用原卷启动，检查健康、Flyway历史、登录、关键工单和附件。发布后的迁移文件不得修改；升级以新增迁移执行。破坏性数据库回滚不由本版自动执行，失败时保留卷、日志和旧镜像，再按经过验证的恢复步骤处理。

数据库备份可通过容器内业务账号读取（密码不放命令参数）：

```bash
mkdir -p backups
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysqldump --no-tablespaces --single-transaction -u "$MYSQL_USER" "$MYSQL_DATABASE"' > backups/serviceops.sql
```

`backups/`包含业务资料，不提交源码。附件应对`service_files`实际卷创建完整归档，并与同一时点数据库备份配套。卷名称有Compose项目名前缀，可通过`docker compose volumes`确认，避免误操作其他项目。

## 对外部署要求

配置HTTPS反向代理及`SESSION_SECURE=true`，限制Web入口来源，配置网关登录限流与请求大小，数据库不开放公网。建立账号审核、密码管理、日志访问限制、漏洞修补、数据库与附件备份、恢复演练、监控和容量评估。本版为单实例会话与定时调度，不直接部署多后端副本。

健康检查只报告可用状态，不开放Actuator其他管理接口。Nginx提供同源代理、SPA回退、禁止嵌套页面和下载类型保护。上传签名检查不等于内容安全扫描，业务要求时接入专门扫描系统。

## 停止与独立验收

`docker compose down`停止项目，保留数据。不要对实际业务环境执行`down -v`。

独立验收使用不同项目名和端口，以全新卷验证迁移与首次启动：

```bash
WEB_PORT=8298 docker compose -p serviceops-qa up -d --build --wait --wait-timeout 240
python3 scripts/smoke.py --url http://127.0.0.1:8298 --allow-test-data
WEB_PORT=8298 docker compose -p serviceops-qa down -v
```

HTTP工具仅接受localhost或127.0.0.1，必须显式允许测试数据。最后只销毁该独立验收项目的容器与卷，不清理任何其他项目资源。镜像和构建缓存可保留复用。
